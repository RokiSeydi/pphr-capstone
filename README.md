# PPHR capstone

Revision project for **CHME0031 — Programming with Python for Health
Research**, MRes AI-Enabled Healthcare, UCL.

Built from the two past papers (January 2026 and 2 September 2025). It has
three parts, which do different jobs:

| | What it is | What it's for |
|---|---|---|
| `drills/` | 209 auto-graded tests across 13 topics | Syntax fluency. Run `pytest`, see what fails, fix it. |
| `mocks/` | Three full 3-hour papers | Exam conditions, timed, sat as a group. |
| `capstone/` | One growing analysis of ED sepsis data | Applying the techniques to an unfamiliar question. |

## Quick start

```bash
make setup           # virtualenv + dependencies  (once)
make drill WEEK=1    # run one week's drills
make progress        # how far through you are
make mock N=3        # sit a timed paper
make lab             # open JupyterLab
```

`make` on its own lists every target.

## The drills

Each week maps to one exam question archetype. Open the module, fill in the
functions, run the tests.

```
$ make drill WEEK=3
tests/test_week03.py::test_triage_chest_pain[yes-yes-yes-...]  PASSED
tests/test_week03.py::test_bmi_category_boundaries             FAILED
```

Every function arrives as a stub with a docstring that fully specifies it —
inputs, output shape, edge cases, worked examples — and a body that raises
`NotImplementedError`. The tests check exactly what the docstring promises,
including the boundary cases where marks are actually lost.

| Week | Topic | Exam archetype |
|---:|---|---|
| 1 | Lists, dicts, indexing | Jan Q1, Sep Q1 |
| 2 | Loops and simulation | Jan Q2, Sep Q3 |
| 3 | Conditionals, decision trees | Jan Q3 |
| 4 | Strings, f-strings, dates | Sep Q2, Q3 |
| 5 | Functions, docstrings, error handling | Jan Q5, Sep Q7, Q9 |
| 6 | Regex on clinical free text | Jan Q6, Sep Q10 |
| 7 | Classes and inheritance | Jan Q7, Sep Q5 |
| 8 | Selecting from a DataFrame | Jan Q4, Sep Q6 |
| 9 | Reading files (including zipped), sorting | Jan Q8, Sep Q8 |
| 10 | Grouping, binning, aggregation | Jan Q10, Sep Q11 |
| 11 | Merging and cross-tabulating | Jan Q11, Sep Q4 |
| 12 | Matplotlib figures | Jan Q9, Sep Q12 |
| 13 | Derived features, logistic regression | Jan Q12, Sep Q12 |

`solutions/` holds a worked answer to every drill. Try first — but the
solutions are commented to explain *why*, not just what, so they are worth
reading once you have had a go.

```bash
make verify     # runs the same tests against solutions/ - always green
```

If `make verify` ever fails, the test is wrong rather than your answer. Worth
running after you add a drill of your own.


This copies the blank paper and its data into `mocks/attempts/<timestamp>/`,
so the original stays clean, and prints the clock times to keep to — half
way, one hour left, pens down, submit by. `mocks/attempts/` is gitignored:
your answers stay on your machine.

Papers 1 and 2 are more useful once, early, before anyone has read the
exemplar solutions.

## The capstone

> Among adults attending the emergency department with suspected sepsis, does
> the NEWS2 score at triage identify the patients who go on to need intensive
> care — and is treatment any faster for those it flags?

`capstone/report.ipynb` is a worked end-to-end analysis: five tables joined,
NEWS2 built from the vital signs, outcomes tabulated by risk band, a
door-to-antibiotics audit, and a logistic regression for ICU admission. Add
a section each week as the module covers new ground.

The clinical domain is deliberately **different** from both past papers —
they use NHS waiting lists, staffing, and diet/blood-pressure data — so the
techniques get applied rather than recalled.

The data is **synthetic**, generated by `scripts/make_capstone_data.py`. No
real patient records are involved. That is the useful part: because the
process generating the outcome is known, `capstone/model.py` can check the
fitted coefficients against the true ones. Every confidence interval should
cover its true value, which tells you the difference between code that works
and an answer that merely looked plausible.

```bash
make data                       # regenerate
.venv/bin/python scripts/make_capstone_data.py --seed 7 --n 5000
```

Re-running with a different seed is a good exercise in itself: which of your
findings survive?

## Requirements

Python 3.10+, and only the libraries the module teaches: pandas, numpy,
matplotlib, statsmodels, jupyterlab. `pytest` for the drills — revision
tooling, not an exam library. Developed against Python 3.13 with pandas 3.1.

**macOS / Linux:** works as-is — `make setup` and the rest of the Quick
start section need nothing extra.

**Windows:** the `Makefile` relies on a Unix shell and on a virtualenv
layout (`.venv/bin/python`) that plain Windows doesn't have, so `make`
won't run in PowerShell or cmd. The fix is **WSL** (Windows Subsystem for
Linux) — a real Linux environment inside Windows, free, and a one-time
setup:

1. Open PowerShell **as Administrator** and run:
   ```powershell
   wsl --install
   ```
2. Restart when it asks. Open **Ubuntu** from the Start menu — first launch
   asks you to create a username and password for that Linux environment
   (separate from your Windows login).
3. Inside that Ubuntu window, everything in this README works exactly as
   written — same commands, same `make` targets, as on macOS or Linux. Clone
   the repo again from inside WSL (your Windows file explorer and the WSL
   filesystem are different places); your Windows-side clone, if you made
   one before installing WSL, isn't used from here.

After that one-time setup, Windows users follow the normal **Quick start**
section above, inside the Ubuntu/WSL terminal, no further translation
needed.

**One WSL/Linux quirk to expect:** `make lab` can fail to auto-open a
browser tab correctly — you might see a plain local folder listing instead
of JupyterLab. If so, ignore that tab and look at the terminal instead:
Jupyter prints a URL like `http://localhost:8888/lab?token=...` — copy
that (with the token) into your browser's address bar by hand. This is a
known Linux/WSL browser-launch issue, not a problem with the project.
